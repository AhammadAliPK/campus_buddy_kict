# Week 6 exercise — why Home can't clear the favourites

The favourites are stored in the _courses list inside _CoursesScreenState. That list is private to the Courses screen. Home and Courses are widgets inside the shells IndexedStack. They don’t know about each other. So when the confirmation screen shows up on Home and the user taps to confirm there’s no way for Home to access the list or call setState to update Courses. That’s why it doesn’t work. To fix this we need state management. The _courses list should be moved out of the Courses screen. Placed in a shared location above both tabs. For example, we could use a ChangeNotifier with Provider. That way both Home and Courses can read the list. Make changes to it.. Whenever the list changes, any screen that displays it will rebuild automatically. When the "clear all favourites" confirmation appears from the Courses tab. The one triggered by the star button in the AppBar. It works fine. That’s because the code runs inside the state that owns _courses. So it has access, to the list and can update it correctly.
